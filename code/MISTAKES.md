# code/ — mistakes

- **Sampling straight from the heavy-tailed latent (no IE scaling) at large κ.** Training at κ = 10² gave NaNs. The posterior has infinite variance for κ ≥ 1/2 (in the Gamma mixture, ν = 2/κ), so rare huge samples blow up the decoder. Fix: train with the independent-equals distribution (σ/√(1+κ), κ̃ = κ/(1+κ)) and drop the scaling only at inference.
- **Reconstruction loss scaling.** An earlier version used `2κ` in the coupled sum and put the 0.5 outside. The coupled sum is `0.5·‖x−x̂‖² ⊕_κ A_xz` with the plain κ.
- **Partition function in the old κ convention (fixed 2026-10-06).** `compute_log_partition_function` normalized (1 + κQ)^−(1+dκ)/(2κ), so it returned the paper's Z at 2κ, while the sampler and exponents used the paper's κ. Mode 7 had the same leftover, log1p(κQ) instead of log1p(κQ/2). All CelebA κ > 0 results before this date were deleted. Check any Z change against a brute-force integral (d = 2 must give 2π for every κ).
- **Shared reconstruction folders (fixed 2026-10-06).** `/content/evaluation_dataset/reconstructions_<κ>…` had no model name, so CVAE and heavy_vae read and skipped each other's images. Folder names now include the model.
- **Coupled divergence terms.** Earlier versions used a separate "information κ", an exponent other than 1/(1+κd/2) on the log partition, and 0.5 factors on A_q and A_p. All three disagree with Theorem `theorem_CFE`. Use κ itself, the exponent 1/(1+κd/2), and no 0.5 on A_q, A_p.
- **Eval-set zip in two places, two layouts (fixed 2026-10-06).** `run.py` mode 2 looked for `<data>/<model>/evaluation_dataset.zip` and extracted it into the Drive folder (1.5 GB of images into `celeba_data/cvae/`). The shell scripts and metric scripts use `<data>/evaluation_dataset.zip` and extract to `/content`. The shell zip also stored the path as `content/evaluation_dataset/…`, which extracts to `/content/content/…`. Now all of them use the dataset-root zip with a top-level `evaluation_dataset/` folder.
- **Corruptions are random and were not shared.** `generate_corrupted_images.py` is unseeded, so a new session makes new corrupted images. Models compared in one table must use the same set. The zip made right after phase 3 is that set. Don't delete it between model runs.
- **RNG restore failed on Colab (fixed 2026-10-06).** `torch.load(..., map_location=cuda)` moves every tensor in the checkpoint to the GPU, including the saved numpy key, so `.numpy()` in `restore_rng_state` crashed. Every mode that loads a checkpoint (2 to 7) failed after training. Fix: `.cpu()` before `.numpy()`. A local syntax check can't catch this, since it only shows up with a GPU.
- **Mode 7 rows of β models keyed by κ (fixed 2026-10-07).** Models 3-4 train with κ = 0, and mode 7 used κ as the row key, so every β run replaced the same `0.0` row and `pipeline_state.py` (which looks for β) reran mode 7 on every resume. The row key is now β for models 3-4.
- **Comparing raw logged ELBO/Recon across κ.** The logged coupled loss carries an offset A_x and weight 1 + κA_x that change by orders of magnitude with κ (Recon at batch 0 is 49,369 at κ = 1e-6 and 208 at 1e-2 for the same network). Compare MSE/pixel and PostVar from `analyze_kappa_collapse.py`, or the mode 7 bound.
- **Learning σ_x to fix the κ = 1e-2 collapse (rejected 2026-10-07, before any run).** With Σ_x = σ²I the weight on the squared error is (1 + κA_x)/σ² ∝ σ^(−2/(1+κd/2)). On CelebA κd/2 = 246 at κ = 1e-2, so σ almost cancels. With the optimal σ ≈ 0.098 (MSE/pixel 0.0097), β_eff goes 25.1 → 24.7 at κ = 1e-2, 1.82 → 1.52 at 1e-3, and 1 → 0.01 at κ = 0. It would widen the gap between κ = 0 and κ > 0, not close it.
- **Mode 7 as "each model's own densities under the natural log" (dropped 2026-10-07).** With the decoder scale fixed at σ = 1 (real pixel error σ ≈ 0.1), the κ > 0 reconstruction term grows like (d_d/2)·log Q, as a Gaussian with σ fitted per image would, while κ = 0 stays linear in Q. The CelebA cvae rows (κ = 0: 45,502; κ = 1: −48,393; κ = 10: −inf from float32 overflow) mostly measured that scale mismatch. Using each model's own heavy-tailed q against a Gaussian prior does not work either: the KL is infinite for κ ≥ 1. Mode 7 now uses the common Gaussian bound (paper lemma `lemma:common_gaussian_evaluation`).
- **Crypto fit with the old κ convention (fixed 2026-10-08).** The first `cryptosData fit.py` used (1 + κt)^(−1/κ) with the score factor 2/σ² and a Γ(1/2κ) normalization, which is the paper's density at 2κ with the wrong exponent, so its κ values (0.5 to 1.9) were not the paper's. The Gaussian baseline also reused the same score with a wrong factor 2, giving −0.19 instead of −1/(2σ²). Now the density is the paper's Z and exponent −(1/κ + d/2), and the tail threshold for variance is κ = 1 (not 0.5), for the mean κ = 2 (not 1).
- **Crypto fit by Hyvärinen score matching (replaced 2026-10-08).** With the paper's density, score matching picked κ = 2 to 18 for BNB, BTC, DOGE and ETH. The fitted peak was far too low (BTC 12 vs 23 empirical, DOGE 4 vs 13) and the mean log-likelihood dropped (BTC 1.54 vs 2.09). The 1D density has a closed-form Z, so use maximum likelihood. Keep the score-matching numbers only as a comparison.
- **Comparing the Hill index with the density exponent (found 2026-10-08).** The Hill estimator gives the exceedance exponent α in P(|r|>x) ~ x^−α, which is 2/κ for the coupled Gaussian. I compared it with 2/κ+1 (the density exponent) and wrongly said ML and Hill agreed. Correct values: ML 2/κ is 2.0 to 3.2, Hill is 2.6 to 4.3, so ML is slightly heavier than Hill and slightly overpredicts 6σ+ days.
- **Whole-sample ML κ on difference series (found 2026-10-08).** On quake, Sabino, San Pedro and NYC rain differences the ML fit went to κ > 100 (a sharp peak with a nearly flat tail), and on GOES and Colorado it put the tail well above the data. Don't read that κ as a tail index there. Use the Hill κ = 2/α, and plot the survival function to see the mismatch.
- **Hill α from one k.** On the pilot series α moves by a factor of 2 over k = 50 to 1000, and k = 50 alone would have kept GOES (3.2) and Colorado out or Sabino in. Report several k and call a series heavy only if α < 2 holds for k ≥ 100 to 200.
- **`open(f, "wb").write(get(url))` creates the file before `get` fails.** GOES years with no report (2017 on) left empty files, which the first run read as data. Fetch first, then open. The empty files were deleted by hand.
- **Repeated the empty-file bug in the wiki job (2026-10-08).** `open(f, "wb").write(get(url))` left a 0-byte `Michael_Jackson.json` when the Wikimedia API answered 429, and the whole job list aborted. Fetch first, sleep 2 s between requests, skip files that exist with size > 0, and let one failed item not stop the other jobs (run them one by one).
- **Differences of a file that is not in time order (found 2026-10-08).** `norwegianfire` has only the year, and the rows are sorted by size inside each year, so the first diff run gave Hill α 0.57 at every k (the jumps between sorted claims). SOA claims and SNAP in-degree (node id) have no time order either. Such series are `RAW_ONLY` in `heavytail_pilot.py`.
- **Power-law density exponent read as the tail index (2026-10-08).** Web in-degree is usually quoted as p(k) ~ k^−γ with γ about 2.1 to 2.7, which gives P(K > k) ~ k^−(γ−1), so α is 1.1 to 1.7 (below 2), not 2 to 3. Web-Stanford measured α ≈ 1.0 to 1.2. Compare α with 2/κ only after subtracting 1 from a density exponent.

- **Running variance as evidence of infinite variance (dropped 2026-10-13).** The ratio of the sample variance on the last tenth of the data to the first tenth depends on where the few largest values fall in time, so it gave growth for some heavy-tailed sets and none for others (Norwegian, Wikipedia, GOES at 0.7 to 1.0). Base the claim on the tail index.
- **ArcGIS grouped queries ignore resultOffset (2026-10-13).** The first `us_wildfire` download paged a `groupByFieldsForStatistics` query by offset; the server returned the same 2000 rows each time and the loop never ended (stopped after 20 min). Split the `where` range instead until each answer has fewer than 2000 rows.
- **Float residues in differences counted as values (2026-10-13).** Differences like 0.3 − 0.2 leave 1e-16 instead of 0, so `a > 0` kept them: the log-binned histogram started at 1e-16 and the whole-curve fit grid was stretched (Guadalupe RMSE 0.27 looked better than the true 0.44). Round differences to 6 decimals before standardizing.
- **Wildfire area as an infinite-variance example (rejected 2026-10-13).** Canada (NFDB) and US (FPA FOD 7th ed.) burned area both bend down at the top (Hill α 2.22 and 2.97 at k = 50), and both have large atoms at rounded sizes (13%, 34% at 0.1 acre). Thresholding at 10 or 100 acres removes atoms but not the bend.
- **Citation counts as an infinite-variance example (rejected 2026-10-13).** OpenAlex articles from 2000 have Hill α 1.9 to 2.05 for k = 50 to 1000, on the boundary, so the infinite-variance claim does not hold.
- **Intermittent rivers for the difference series (rejected 2026-10-13).** Sabino (40%) and San Pedro (30%) have many zero daily differences because the stream is dry, which no smooth density fits. Use a perennial, unregulated river.
